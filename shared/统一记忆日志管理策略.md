# 统一记忆日志管理策略

**适用对象**：辉哥的全部 Grok Agent 套件  
**中央仓库**：https://github.com/Simon66-workshop/66agent  
**本地工作区**：/Volumes/2T扩展盘/Agent文件  
**最后更新**：2026-08-19

---

## 1. 核心原则

1. **单一真实来源**：中央 GitHub 仓库为权威最新版。
2. **读取与同步顺序（MUST）**：
   - **先读取 GitHub 最新内容**
   - **再同步更新本地** `/Volumes/2T扩展盘/Agent文件`
3. **分 Agent 独立维护**：每个 Agent 只维护自己的工作记忆日志。
4. **编排总控负责全局视角**：维护跨 Agent 任务状态与全局索引。
5. **更新触发**：
   - 重要操作后立即更新对应日志
   - 辉哥说「更新」「同步」时：以 GitHub 为准拉取后写回本地，必要时再推送本地新增变更到 GitHub，并回报路径与变更摘要
6. **Skill 自动双写（MUST）**：
   - 新建或更新 `skills/` 下任何 skill，立刻同时写入 GitHub 和本地，不必等辉哥再说「更新」
   - 同步更新 `skills/README.md` 技能列表
   - 本地路径：`/Volumes/2T扩展盘/Agent文件/skills`

## 3. 工作记忆日志标准结构

1. 用户偏好 / 持久信息
2. 当前活跃事项
3. 近期日志（最新在前，带标签）
4. 待跟进 / 开放问题
5. 专项扩展（研究：预判校准；内容：风格样本）

推荐标签：`[偏好]` `[任务]` `[洞察]` `[预判]` `[反馈]` `[风格]` `[机会]` `[校准]` `[路由]`

---

## 4. 更新与归档规则

- **会话开始 / 辉哥要求同步**：先读 GitHub → 再更新本地
- **重要操作后**：更新对应日志；需要持久化时推 GitHub，并同步本地
- **辉哥说「更新」**：GitHub 与本地双边对齐，回报变更摘要
- **新建 / 更新 skill**：立刻双写 GitHub `skills/` 与本地 `skills/`
- **每月轻量归档**：旧内容摘要化
- **跨 Agent 信息**：由编排总控在全局记忆中记摘要，不直接改其他 Agent 日志

---

## 5. 编排总控额外职责

- 维护全局活跃跨 Agent 任务表
- 记录各专业 Agent 近期状态摘要
- 复杂任务结束后更新全局记忆日志

---

## 6. 安全与边界

- 禁止写入 token、密码、设备码
- 不确定内容先向辉哥确认
- 不要跨 Agent 直接修改对方日志

---

本策略为所有 Agent 的强制协议。读取顺序已统一为：**GitHub → 本地**。Skill 新建/更新自动双写。
