# 统一记忆日志管理策略

**适用对象**：辉哥的全部 Grok Agent 套件  
**中央仓库**：https://github.com/Simon66-workshop/66agent  
**本地工作区**：/Volumes/2T扩展盘/Agent文件  
**最后更新**：2026-08-18

---

## 1. 核心原则

1. **单一真实来源**：所有规范文件与工作记忆日志以本仓库 + 本地工作区为唯一权威。
2. **分 Agent 独立维护**：每个 Agent 只维护自己的工作记忆日志，互不直接修改。
3. **编排总控负责全局视角**：维护跨 Agent 任务状态与全局索引。
4. **读写顺序**：优先本地 → 再 GitHub。
5. **更新触发**：
   - 重要操作后立即更新对应日志
   - 辉哥说「更新」「同步」时，必须同时更新本地 + 推送到 GitHub，并回报路径与变更摘要

## 3. 工作记忆日志标准结构（所有 Agent 必须遵循）

1. **用户偏好 / 持久信息**
2. **当前活跃事项**
3. **近期日志**（最新在前，带标签）
4. **待跟进 / 开放问题**
5. **专项扩展**（研究助理：预判校准表；内容创作：风格样本与反馈）

### 推荐标签
`[偏好]` `[任务]` `[洞察]` `[预判]` `[反馈]` `[风格]` `[机会]` `[校准]` `[路由]`

---

## 4. 更新与归档规则

- **会话开始**：优先读取本地对应日志，读不到再读 GitHub。
- **重要操作后**：立即更新日志。
- **辉哥说「更新」**：双边同步（本地 + GitHub），回报变更摘要。
- **每月轻量归档**：旧内容摘要化，保留可复用洞察与校准记录。
- **跨 Agent 信息**：由编排总控在全局记忆中记录摘要，不直接改其他 Agent 日志。

---

## 5. 编排总控的额外职责

- 维护全局活跃跨 Agent 任务表
- 记录各专业 Agent 的近期状态摘要
- 在复杂任务结束后，更新全局记忆日志

---

## 6. 安全与边界

- 禁止写入 token、密码、设备码等敏感信息
- 不确定内容先向辉哥确认再写入
- 不要跨 Agent 直接修改对方日志

---

本策略为所有 Agent 的强制协议。更新时请同步到各 Agent 规范文件的「记忆与日志维护协议」部分。
