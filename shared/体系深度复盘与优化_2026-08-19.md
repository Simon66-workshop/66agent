## 2. 深度复盘：什么有效 / 什么无效

### 有效（保留并强化）
1. **专业分工** — 研究不做创作，办公不做深度调研
2. **外部化记忆** — MD + GitHub 比塞进系统提示词更可维护
3. **先 GitHub 再本地** — 单一真实来源清晰
4. **P0 只报命中** — 符合「好 Agent 不骚扰」
5. **研究证据分层** — 事实 / 推断 / 预判 + 置信度
6. **内容铁律** — 去 AI 味 + 禁止词，对 66Workshop 有业务价值

### 无效 / 过重（应收敛）
1. **编排总控偏薄** — 规范最短，路由示例与学习闭环未真正跑通
2. **skills 膨胀且质量不均** — 有的很完整，有的只有几百字占位
3. **ChatGPT 四份早报 + Grok 晨间** — 信息入口过多，合并成本在辉哥身上
4. **P0 仅有规则无执行** — 规范写了，自动化未落地
5. **多模型写码无固化分工** — Codex / Cursor / Opus / Grok / Fable 易抢方向
6. **README 过时** — 未反映当前完整结构

### 结构性风险
- Bot 之间不会自动互相调用，跨 Agent 仍依赖辉哥粘贴/转发
- 「学习闭环」写在规范里，实际很少强制执行
- 小红书数据源清单有重复文件（两份相近）
- 根目录与 shared/ 的统一记忆策略有双份

## 3. 一次优化：收敛原则（Operating System）

### 原则 A：三个入口，不再增加
1. **晨间总控**（Grok 办公 08:30）— 唯一日报入口
2. **P0 事件** — 只在命中时推
3. **周度战略** — 周一合并，不散落每日

ChatGPT 简报继续自己看，只把「今日动作 + 选题 Top3」贴进晨间入口。

### 原则 B：写码三角
- **Codex**：主执行
- **Cursor Ultra**：主编辑器
- **Opus 4.5**：架构与难题
- **Grok 编程助理**：拆解 / 验收 / 审查 / 写回 skills
- **Fable 5**：对照，非默认路径

### 原则 C：知识只写一处
- 稳定 SOP → skills/
- 会话状态 → 各 Agent 工作记忆日志
- 跨 Agent 共识 → shared/
- 禁止同一内容在两处各维护一份长文

### 原则 D：学习闭环最低标准
重要任务结束后必须产出 1–3 条可复用条目，写入 skills 或对应记忆；否则视为未完成。
