# 代码项目与工作长任务 · 默认协作模式（MUST）

**生效**：2026-09-15  
**适用范围**：所有涉及 GitHub 仓库、代码开发、修复、测试、生产验证、独立审计，以及 ChatGPT Work 类长任务  
**原则口号**：**仓库就是交接面**  
**例外**：仅当辉哥在某次任务中明确要求不同流程时，才可偏离本模式  

---

## 1. 默认闭环

```
执行者自主产证
  → 自行提交并发布到对应仓库的功能/审核分支
  → 提供固定提交 SHA 的 GitHub URL
  → ChatGPT（或指定独立审计方）按固定提交独立复审
```

跨线程、跨模型、跨 Work 任务的**唯一稳定交接点**是：  
**对应仓库的固定 commit SHA**（及其目录树 / README / 判决文件的 permalink）。  
不要依赖聊天上下文或本地临时文件作为交接面。

---

## 2. 执行者义务（每个阶段结束后 MUST）

1. **自行生成审计材料**（按阶段需要，缺一不可则写明缺口）：  
   阶段结论、机器可复核判决、测试日志、证据文件、README、哈希清单、公开清单等。
2. **自行提交并发布**到对应 GitHub 仓库的功能分支 / 审核分支。  
   **辉哥不承担**下载、上传、ZIP 转运或手工搬运证据。
3. **发布后必须给出固定提交链接**，优先同时提供：  
   - commit permalink（`.../commit/<SHA>`）  
   - 证据目录树 permalink  
   - README permalink  
   - 最终判决文件 permalink  
   **禁止**只甩会漂移的分支 URL。
4. **发布后必须自行外读复核**：用外部可见的 commit / tree / blob 与本地 SHA256 对照，确认已真正交付。  
   **不能**仅凭「push 成功」宣称已交付。
5. **认证受阻时**：优先用已有授权路径（本机 keyring、`gh`、GitHub 连接器/API）。  
   **不宜默认**要求辉哥提供 PAT、导出 token，或手动迁文件。
6. **结论分层，禁止冒充**：  
   - 产品结论  
   - 证据结论  
   - 历史事实  
   - 当前状态  
   不得把「测试通过 / 工程终端 PASS / 历史收据 / 候选版本 / 执行者自报」冒充为**独立生产验收**。
7. **证据落点**：优先放仓库内 `audit/`、`receipts/`、封存目录等约定路径；**保留失败尝试与历史回执，不覆盖历史证据**。
8. **默认不让用户当搬运工**。只有连接器与现有授权路径全部不可用时，才可请求辉哥协助搬运。

---

## 3. 独立审计方义务（ChatGPT Work / 指定复审）

1. 在拿到**固定提交链接**后，默认做独立复审。  
2. **直接读取仓库**中的代码、结论与证据；**不继承**执行者「已完成 / 已通过」判断。  
3. 按证据重判：`PASS` / `BLOCKED` / `FAIL`（或任务约定等价标签），并给出下一阶段任务。  
4. **只有当前阶段独立验收通过后**才进入下一阶段。  
5. 不合格：**不得**降级标准、补写假证据或绕过阻断推进。

---

## 4. 与既有铁律的关系

- 不推 `main`（除非辉哥当场点名）。Draft / 审核分支用于交接。  
- 产出文件优先落对应**业务仓库**的审计目录；办公侧摘要可双写 `66agent` 与 2T。  
- Astra / 跨模型独立复审：证据一律先上 GitHub，再出提示词；本地路径只作备份（2026-09-15）。  
- 密钥、PAT、设备码不准写进规范、日志、聊天或 git。

---

## 5. 一句话检查清单

| 问 | 必须答 |
|---|---|
| 证据在哪？ | 仓库内固定路径 + commit SHA |
| 链接会不会漂？ | 用 commit/blob permalink，不用裸分支 |
| 谁搬运文件？ | 执行者；默认不是辉哥 |
| 谁能说验收过？ | 独立审计按证据重判；不是执行者自报 |
| 失败材料呢？ | 保留历史，不覆盖 |
