# Hotmail 邮件（Outlook.com）

辉哥 Hotmail 没有 Outlook 连接器。收发一律走已登录的 Outlook 网页。按「一个箱一条线」管：每个账号单独切、单独读、单独发，互不混。

适用：查收、搜信、读验证码、起草发出。Gmail 是另一条线，不要和 Hotmail 混。

## 账号

| 账号 | 显示名 | 切箱入口 |
| --- | --- | --- |
| jari6688@hotmail.com | jari wu | https://outlook.live.com/mail/0/?login_hint=jari6688@hotmail.com |
| simonwu.chi@hotmail.com | wu simon | https://outlook.live.com/mail/0/?login_hint=simonwu.chi@hotmail.com |

- 切箱只用 `login_hint` 链接，最稳。
- 右上角头像能看到两个账号，但点击经常切不过去。
- 旧标签也可能串会话，不要只靠点标签判断当前是哪个箱。
- 看页面左下角或文件夹上方的邮箱地址，确认当前箱再动手。
- 会话长期有效。不要登出一个保另一个。
- 碰到登录墙 / 2FA：交给辉哥登，不问、不看、不代填密码。
- 加新箱：打开登录页，交给辉哥登一次，登好再写入本文件。

辉哥没指定箱时：先问从哪个箱查/发。只说「Hotmail」且能从发件人判断时，两个都扫，报清楚来自哪个箱。

## 复盘（2026-08-19 实测）

1. 无 Outlook MCP，装连接器是弯路。网页会话可用。
2. 多账号能同时在线，但 Outlook 网页的账号切换不可靠。实测点头像切到 jari6688 没换箱；旧标签也会回到另一个会话。`login_hint` 才是稳定切法。
3. 必须真正打开对应收件箱再报状态，不能只看账号列表就当已读到。
4. 验证码信和「新登录通知」长得很像。前者正文有 6 位数字，后者没有码。
5. 码会过期。上一轮记住的码作废，每次重读最新那封。
6. 发信必须先确认发件箱和正文。没点头不发。辉哥已经明确说「发」时，按他说的箱和收件人直接发。
7. 页面可能弹出 Outlook 手机 App 二维码，挡阅读。关掉再读，不要当成邮件内容。

## 查收

1. 用 `login_hint` 打开指定箱。
2. 核对页面上的邮箱地址。
3. 看收件箱「重点」，必要时看「其他」和垃圾箱。
4. 回报：哪个箱、未读数、最新几封（发件人、主题、时间，上海时间）。
5. 不编造未读数和正文。

## 验证码

1. 切到指定箱，点开最新对应发件人（ChatGPT / OpenAI / Microsoft）。
2. 只报「临时登录代码 / 验证码」正文里的数字。
3. 「New sign-in / 新登录通知」没有码，不要当成验证码。
4. 回报格式：哪个箱、码、哪家、邮件时间。
5. 不把验证码发给别人或别的助理，除非辉哥当场要。

示例：
- jari6688@hotmail.com / ChatGPT / 12:27 / 786820（有码，报这个）
- 同箱 12:28 OpenAI New sign-in（无码，只报通知）

## 发信

1. 先确认从哪个箱发。辉哥已经指定箱和收件人时，按指定发。
2. 用 `login_hint` 切到该箱，再点写邮件。
3. 起草：收件人、主题、正文。
4. 若辉哥只说「发测试」且未给正文：主题 `Hotmail 测试`，正文写清发件箱和上海时间。
5. 若尚未明确说发：把发件箱、收件人、主题、正文给辉哥看，等他说发再发。
6. 发出后回报：哪个箱、发给谁、主题、时间。到「已发送」核对。

## 禁止

- 不编造未读数、验证码、邮件内容。
- 不在没登录时改走 Gmail，或让辉哥截图交差。
- 不把两个箱的信混在一条回复里却不标明来源。
- 不把密码、token、设备码写进本文件或日志。
