# 多模型编程分工 SOP

**更新**: 2026-08-19  
**适用**: 编程助理 + 辉哥日常写码

---

## 1. 角色分工（固定）

| 角色 | 工具 | 职责 |
|------|------|------|
| 主执行 | **Codex** | 多文件改动、按计划落地、跑通任务 |
| 主编辑器 | **Cursor Ultra** | 读仓库、局部修改、导航、快速试错 |
| 架构顾问 | **Opus 4.5** | 复杂设计、边界情况、长上下文方案对比 |
| 体系与监督 | **Grok 4.6 编程助理** | 拆任务、验收标准、审查、学习闭环写回 66agent |
| 对照执行 | **Fable 5** | 同一任务第二解法；仅在主路径卡住时启用 |

**原则**：同一时刻只有一个「主执行」。默认 Codex，不默认五模型并行改同一处。

---

## 2. 标准流程

```
1. 辉哥提需求
2. 编程助理：目标 / 范围 / 步骤 / 验收标准 / 风险（先 GitHub 读最新规范）
3. Codex 或 Cursor 执行（不扩 scope）
4. 卡住或需架构判断 → Opus 4.5
5. 需要第二路径 → Fable 5
6. 编程助理：对照验收标准审查
7. 可复用坑点 → 写入 skills/ 或工作记忆 → 推 GitHub
```

---

## 3. 对编程助理的固定口令

**开任务：**
```
先去 GitHub 读最新编程规范与 skills，再同步本地。
把需求拆成：目标、文件范围、步骤、验收标准、风险。
主执行 Codex，难点备用 Opus，对照用 Fable。
```

**审查：**
```
对照验收标准审查本次实现：风险、可简化点、应写入 SOP 的坑。
```

**环境：**
```
检查本地环境（Ollama/依赖/关键路径），给出验证步骤；改系统前先确认。
```

---

## 4. 对 Codex / Cursor 的固定约束

- 严格按验收标准，不扩 scope
- 改完列出：变更文件 + 如何验证
- 不碰密钥；不擅自做不可逆系统操作
- 与 66agent 规范冲突时，以仓库最新规范为准

---

## 5. 完成定义

任务完成 = 代码可验证 + 验收标准勾完 +（若有新坑）已写入 skills 或记忆并准备同步 GitHub。
